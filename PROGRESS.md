**Buffer-overlap de-duplication (2026-07-06, pre-Phase-7, user-requested):** the user flagged that capturing two short text lines just below one another causes their 5% buffer margins to collide — and if the lines are tightly packed, each buffer reaches into the *other* line's text, so the same line gets extracted into both passages and shows up twice in semantic/chat search. Fixed by chopping the colliding buffers to meet at the midpoint of the gap between the two raw (un-buffered) drag regions.

New helpers in `lib/capture.js`: `rawBoundsOf` (un-buffered drag extent), `bufferOverlapChop` (returns the gap-midpoint chop line when two raw selections have a gap but their buffers collide; returns null when the raw regions themselves overlap — i.e. it's really one region — or when the buffers don't actually collide), and `cropImageRegion` (re-crops an already-captured JPEG data URL to a tighter sub-region). **Key safety property, verified numerically:** the chop line always sits inside the gap (below the upper raw region, above the lower one), so chopping only ever trims *buffer margin*, never any text the user actually dragged over — even a spurious chop (e.g. from a stale capture after the camera moved) can't eat real content.

Both directions are handled, so the shared region ends up in *neither* passage rather than both:
- **Forward** (new capture): its colliding side is chopped before its crop is taken — clean, synchronous.
- **Backward** (previous capture, already extracted): `CaptureView` now retains each recent capture's crop + bounds transiently *in memory* (not storage — consistent with the "don't store images" change above) in `recentCapturesRef`, with a `savedPromise` resolving to the passage id once saved. When a later overlapping capture arrives, `reChopPrevious` waits for that promise, re-crops the retained image to the trimmed bounds, re-extracts, and `updatePassage`s the text + bounds. Fully guarded: if the previous never saved, was deleted, was merged away, or the re-extraction errors, the previous passage is left exactly as-is. Overlap matching is limited to captures within a 20s window (the "camera hasn't moved" assumption, consistent with continuation detection's existing static-camera assumption).

**Known limitation:** the backward re-extraction costs one extra API call per overlapping pair and briefly (a few seconds later) updates the previous passage's text in place — invisible during active capture, but worth knowing. Deep stacks (3+ captures all mutually overlapping in quick succession) are handled pairwise and compose via `Math.min`/`Math.max` clamping, but a rare double-re-chop race on a middle capture could leave it slightly less tightly trimmed than ideal; acceptable for the prototype.

**New: `lib/theme.js`** — a small theme system. Four themes (`Ink & Gold`, `Warm Paper` default, `Sage Study`, `Faded Linen`), each a set of CSS custom properties (`--bg`/`--surface`/`--raised`/`--fg`/`--acc`/`--fill`/`--on-fill`/`--on-acc`/`--radius`) applied to `document.documentElement`. Colors used for text/fills are stored as space-separated RGB channels (e.g. `"232 213 176"`) so they can be composed with alpha at the call site (`rgb(var(--fg) / .5)`) — this is what makes translucent overlays/borders work throughout the redesigned components. Accent color and corner radius are independently overridable and persisted (`getStoredAccent`/`setStoredAccent`/`getStoredRadius`/`setStoredRadius`); `resolveTheme` computes a luminance-correct `onAcc` (dark vs light text) when the accent is customized. Applied synchronously on `App.jsx`'s initial render (not in a `useEffect`) so the very first paint already reflects the saved theme.

**Styling approach:** Tailwind is still CDN-loaded (no PostCSS build step), which can't reliably do CSS-var-driven dynamic colors via its arbitrary-value syntax through the Play CDN's JIT. Settled on a hybrid: inline `style={{...}}` for anything theme-token-driven, Tailwind utility classes (including arbitrary pixel values) for static layout/spacing/typography. Used consistently across every touched component.
